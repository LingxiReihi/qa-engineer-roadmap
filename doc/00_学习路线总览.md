## 四、陪练式教学协议

### 4.1 每日固定 7 部分流程

每天说一句「**开始 Day X**」，AI 按 7 部分输出：

| 部分 | 内容 | 原则 |
|------|------|------|
| ① 今日目标 | 3~5 条，明确「今天结束应能做到什么」 | 可验证 |
| ② 理论课 | 只讲当天必须掌握的知识 | 每个概念：定义 + 示例 + 坑 |
| ③ 示例代码 | 少量、能跑、标注关键点 | ≤ 30 行，含反例 |
| ④ 今日练习 | 10 分钟能完成的思考/编码小题 | 不查资料，每题 ≤ 5 行 |
| ⑤ 今日实战任务 | 模拟真实测试开发工作 | 含正常+异常+边界 |
| ⑥ 提交作业 | 代码 + 运行结果 + 测试场景 + 问题 | 按模板提交 |
| ⑦ Code Review | 7 维度评分 + 修改建议 | 不给答案 |

### 4.2 Code Review 7 维度

| 维度 | 检查点 |
|------|--------|
| 正确性 | 功能是否符合需求；边界是否覆盖 |
| 代码结构 | 函数是否单一职责；模块是否分层 |
| 命名 | 变量/函数/模块名是否表意 |
| 异常处理 | 是否捕获该捕获的异常；是否吞掉不该吞的 |
| 可读性 | 是否能被第三人读懂；注释是否恰当 |
| 测试思维 | 是否考虑了正常/异常/边界/并发 |
| 工程习惯 | 虚拟环境、.gitignore、类型注解、文档字符串 |

### 4.3 评分系统 S/A/B/C/D

| 综合 | 判定 | 后续 |
|------|------|------|
| S / A | ✅ 通过 | 进入下一天 |
| B | ⚠️ 修改后通过 | 重交修改版 |
| C / D | ❌ 需要重做 | 重学 + 重交 |

**铁律**：代码运行成功 ≠ 通过。`print("Hello")` 能跑，但不代表写得好。

### 4.4 不代写原则

**可以做的**：讲思路、指出异常、给测试方向、点评问题、解释概念、提供反例
**不做的**：直接给答案、贴练习答案、帮你写代码、跳过 Review、降低标准

### 5.2 进度映射规则

| Review 评分 | mastery | status |
|-------------|---------|--------|
| S | 0.9 ~ 1.0 | mastered |
| A | 0.7 ~ 0.9 | mastered |
| B | 0.5 ~ 0.7 | in_progress |
| C | 0.3 ~ 0.5 | in_progress |
| D | 0.0 ~ 0.3 | not_started |

### 5.3 掌握度模型

- **证据驱动**：mastery 由 `mastery show / apply` 计算，不手工拍数值
- **晋级门槛**：mastery≥0.85 + 证据≥5 + 阶梯段≥3 + 独立成功 + 变式迁移 + 最近无错
- **降级机制**：错误类型 × 重复次数 × 时间衰减（14 天半衰期）
- **confidence 与 mastery 独立**：confidence 反映证据量，mastery 反映当前水平
