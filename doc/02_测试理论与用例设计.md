# 02 · 测试理论与用例设计

> **阶段时长**：2 周（预计 Day 22~35）
> **前置**：阶段 01（Python 基础）验收通过
> **核心目标**：拿到需求文档能写出结构化用例
> **状态**：⏳ 待开始（到达此阶段时完善详细计划）

---

## 一、阶段概述

测试理论不是"背概念"，而是**建立一套思考问题的框架**。拿到一个需求文档，你应该能在 15 分钟内列出 20+ 条测试用例。

本阶段解决的核心问题：
- 怎么想测试点？（黑盒方法）
- 用例怎么写？（文档规范）
- 测试怎么计划？（测试计划）
- 日志怎么看？（Linux 日志分析）

---

## 二、核心能力目标

完成本阶段后，你应该能做到：

- [ ] 用等价类划分 + 边界值分析为一个功能列出完整测试点
- [ ] 用场景法 + 因果图为复杂业务流程设计用例
- [ ] 用错误推测法补充遗漏用例
- [ ] 写出结构化用例（ID / 标题 / 前置 / 步骤 / 预期 / 优先级）
- [ ] 为"登录功能"写出 30+ 条用例，覆盖正常/异常/边界/安全
- [ ] 写一份小项目的测试计划
- [ ] 用 grep/awk 从日志中提取 ERROR/WARNING

---

## 三、训练任务（概览）

| 训练 | 主题 | 核心知识点 | 验收 |
|------|------|-----------|------|
| T2-1 | 等价类划分 | 有效/无效等价类、输入域划分 | 为一个功能列出等价类表 |
| T2-2 | 边界值分析 | 最小/最大/临界/越界 | 每个等价类 2~4 个边界值 |
| T2-3 | 场景法 | 基本流/备选流/异常流 | 复杂业务流程场景图 |
| T2-4 | 因果图 | 条件-动作对、约束 | 登录功能因果图 |
| T2-5 | 错误推测法 | 经验驱动的异常场景 | 补充 10+ 条非常规用例 |
| T2-6 | 用例文档规范 | ID/标题/前置/步骤/预期/优先级 | 用例模板标准化 |
| T2-7 | 登录功能实战 | 30+ 用例设计 | 覆盖正常/异常/边界/安全 |
| T2-8 | 测试计划 | 范围/策略/资源/进度/风险 | 小项目测试计划 |
| T2-9 | Linux 日志分析 | grep/awk/sed/log 工具 | ERROR/WARNING 提取 |

---

## 四、关键知识点（待展开）

- **黑盒测试方法**：等价类、边界值、场景法、因果图、错误推测
- **白盒测试基础**：语句覆盖、分支覆盖、路径覆盖（了解）
- **测试用例文档**：ID 编号规范、步骤描述规范、预期结果规范
- **测试计划**：测试范围、测试策略、测试资源、测试进度、风险评估
- **Linux 日志**：`grep` / `awk` / `sed` / `less` / `tail -f`
