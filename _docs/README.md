# Python 测试学习路径 · 从 0 到测试开发

> **目标读者**：有一定编程基础、希望系统学习 Python 测试、最终以「测试开发（SDET / QA Engineer）」为职业目标的自学者。
> **总时长**：6 ~ 9 个月（每天投入 2 ~ 3 小时）。
> **配套仓库**：建议与 `100DayPython` 主线课程并行，把本路径当作「专业方向课」。

## 三、学习方法论（必读）

### 1. 三段式学习循环

每个阶段、每个知识点，都按这个循环走：

```
学 → 练 → 复盘
│   │   └─ 写一段"今天学到什么 + 哪里卡住"的笔记
│   └─ 必须亲手敲代码、跑起来、看到结果（不只是看）
└─ 看文档/教程，理解"为什么"而不是"怎么做"
```

> **反模式**：只看不练、抄代码不报错就跳过、不写测试用例直接跑框架。

### 2. 「测试先行」思维训练

从阶段 01 开始，每写一个新功能，先问自己三个问题：

1. 这个功能**正常情况下**怎么用？
2. 有什么**异常情况**会触发它？
3. 我在什么**边界值**上会出错？

把这三个问题写下来，就是最原始的用例设计。

### 3. 项目驱动，不要"学完再练"

- 阶段 01 ~ 02：用 `100DayPython` 的练习作为训练场。
- 阶段 03 起：每个阶段都配一个**小项目**作为练手（见各阶段文末）。
- 阶段 08：完成一个完整的测试项目作为**作品**（简历核心）。

### 4. 每日节奏建议

| 时长 | 动作 |
|---|---|
| 15 分钟 | 回顾昨天笔记 + 今日目标 |
| 60 ~ 90 分钟 | 学习新知识（文档/视频/源码） |
| 60 ~ 90 分钟 | 动手训练（写代码 + 写测试） |
| 15 分钟 | 复盘笔记 + 明日预告 |

> 周末可以做一个"半天挑战"：用一个完整的小任务串起本周学到的所有内容。

## 四、贯穿线：你的成长轨迹

```
阶段 01 → 能看懂别人写的 Python 代码，能写 50 行小程序
阶段 02 → 拿到一个功能描述，能列出 20+ 条测试用例
阶段 03 → 用 pytest 给一个模块写完整单元测试，覆盖率 > 80%
阶段 04 → 为一个真实 API 写自动化测试套件，10+ 接口全覆盖
阶段 05 → 用 Playwright 写一个登录流程的 UI 自动化
阶段 06 → 用 Locust 压测一个接口，输出含 P95/P99 的报告
阶段 07 → 把测试套件接入 GitHub Actions，PR 自动跑
阶段 08 → 设计一个分层测试框架，从零搭建一个测试项目
       → 简历上有一个可展示的作品链接
```

## 五、如何使用本路径

1. **第一次打开**：通读 `00_学习路线总览.md`，建立全局认知。
2. **每周开始**：打开对应阶段的文档，读「本周目标」「训练任务」「验收标准」。
3. **训练完成**：在文档末尾的「打卡表」里打勾（可复制到你的笔记里）。
4. **遇到卡点**：先看文档里的「常见陷阱」，再查阶段附录资源。
5. **阶段结束**：按「阶段验收」自检，通过则进入下一阶段。
