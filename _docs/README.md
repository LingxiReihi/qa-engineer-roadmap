# Python 测试学习路径 · 从 0 到测试开发

> **目标读者**：有一定编程基础、希望系统学习 Python 测试、最终以「测试开发（SDET / QA Engineer）」为职业目标的自学者。
> **总时长**： **180 天（26 周）**，每天投入 2 ~ 3 小时。
> **教学方式**： **陪练式** —— 每日按「学习 → 实战 → 提交 → Code Review → 修正 →
> 验收」流程推进（详见 [10_陪练式教学协议.md](./10_陪练式教学协议.md)）。
> **作品集仓库**：从 Day 1 建立 `qa-engineer-roadmap` 仓库，180
> 天所有成果都放进去（详见 [11_作品集仓库指南.md](./11_作品集仓库指南.md)）。
> **配套仓库**：建议与 `qa-engineer-roadmap` 主线课程并行，把本路径当作「专业方向课」。

## 三、学习方法论（必读）

### 1. 三段式学习循环

每个阶段、每个知识点，都按这个循环走：

```
学 → 练 → 复盘
│   │   └─ 写一段"今天学到什么 + 哪里卡住"的笔记
│   └─ 必须亲手敲代码、跑起来、看到结果（不只是看）
└─ 看文档/教程，理解"为什么"而不是"怎么做"
```

> **反模式**：只看不练、抄代码不报错就跳过、不写测试用例直接跑框架。

### 2. 「测试先行」思维训练

从阶段 01 开始，每写一个新功能，先问自己三个问题：

1. 这个功能 **正常情况下**怎么用？
2. 有什么 **异常情况**会触发它？
3. 我在什么 **边界值**上会出错？

把这三个问题写下来，就是最原始的用例设计。

### 3. 项目驱动，不要"学完再练"

- 阶段 01 ~ 02：用 `qa-engineer-roadmap` 的练习作为训练场。
- 阶段 03 起：每个阶段都配一个 **小项目**作为练手（见各阶段文末）。
- 阶段 08：完成一个完整的测试项目作为 **作品**（简历核心）。

### 4. 每日节奏建议

| 时长         | 动作                         |
|--------------|------------------------------|
| 15 分钟      | 回顾昨天笔记 + 今日目标      |
| 60 ~ 90 分钟 | 学习新知识（文档/视频/源码） |
| 60 ~ 90 分钟 | 动手训练（写代码 + 写测试）  |
| 15 分钟      | 复盘笔记 + 明日预告          |

> 周末可以做一个"半天挑战"：用一个完整的小任务串起本周学到的所有内容。

### 5. 每日固定 7 部分流程（陪练式核心）

每天开始时说一句「 **开始 Day X**」，AI 会按 7 部分输出当天课程：

```
① 今日目标 → ② 理论课 → ③ 示例代码 → ④ 今日练习 → ⑤ 今日实战任务
→ ⑥ 提交作业 → ⑦ Code Review
```

**Code Review 7 维度**：正确性 / 代码结构 / 命名 / 异常处理 / 可读性 / 测试思维 / 工程习惯

**评分 S/A/B/C/D**：综合 B 以上通过；C/D 需重做。

**两条铁律**：

- 不代写作业 —— 讲思路、讲异常、讲测试点，但不给最终答案
- 通过 Review 才进下一天 —— 代码能跑 ≠ 通过

详见 [10_陪练式教学协议.md](./10_陪练式教学协议.md)。

### 6. 作品集仓库（Day 1 开始建）

从 Day 1 建立 `qa-engineer-roadmap` 仓库，180 天所有学习成果都放进去：

```
qa-engineer-roadmap/
├── 01-python/          ← 阶段 01
├── 02-software-testing/
├── 03-linux-git/
├── 04-pytest/
├── 05-api-automation/
├── 06-ci-cd/
├── 07-web-mobile/
├── 08-performance/
├── 09-engineering-basics/
├── 10-final-project/   ← QA Automation Platform
└── .github/workflows/  ← CI 自动跑测试
```

每周一个项目，每日一次 commit，评分记录在 README 里。180 天后，这个仓库就是你的 **测试开发作品集**，面试时直接打开。

详见 [11_作品集仓库指南.md](./11_作品集仓库指南.md)。

### 7. 工程环境补充（Linux + SQL）

原路径完全没讲 Linux 和 SQL，这是测试开发的日常技能：

- **Linux 日志分析**：grep / awk 找出 ERROR、统计 Top N
- **Linux 性能观察**：top / free / iostat / ss 定位瓶颈
- **SQL 测试数据**：准备、验证、清理测试数据

建议穿插在阶段 02~04 之间学习（10~14 天）。

详见 [12_工程环境补充_Linux_SQL.md](./12_工程环境补充_Linux_SQL.md)。

## 四、贯穿线：你的成长轨迹

```
阶段 01 → 能看懂别人写的 Python 代码，能写 50 行小程序
阶段 02 → 拿到一个功能描述，能列出 20+ 条测试用例
阶段 03 → 用 pytest 给一个模块写完整单元测试，覆盖率 > 80%
阶段 04 → 为一个真实 API 写自动化测试套件，10+ 接口全覆盖
阶段 05 → 把测试套件接入 GitHub Actions，PR 自动跑
阶段 06 → 用 Playwright 写一个登录流程的 UI 自动化
阶段 07 → 用 Locust 压测一个接口，输出含 P95/P99 的报告
阶段 08 → 设计一个分层测试框架，从零搭建一个测试项目
       → 简历上有一个可展示的作品链接
```

## 五、如何使用本路径

### 第一次打开（Day 0）

1. 通读 [00_学习路线总览.md](./00_学习路线总览.md)，建立全局认知。
2. 通读 [10_陪练式教学协议.md](./10_陪练式教学协议.md)，理解陪练流程和评分标准。
3. 按 [11_作品集仓库指南.md](./11_作品集仓库指南.md) 建立 `qa-engineer-roadmap` 仓库。
4. 按 [01_Python基础与测试入门.md](./01_Python基础与测试入门.md) 的 Day 0 完成工程环境准备。

### 每天

```
1. 说一句「开始 Day X」
2. AI 按 7 部分输出课程
3. 自己写代码、写测试
4. 提交作业给 AI Review
5. 根据 Review 结果修改
6. 通过后 git commit + push
7. 更新 teach.db 进度
```

### 每周

1. 完成一个阶段项目（见各阶段文末）。
2. 提交项目验收，获得综合评分。
3. 更新作品集仓库 README 的评分表。

### 每阶段结束

1. 按「阶段验收」自检。
2. 全部打勾 → 进入下一阶段。
3. 未打勾 → 补完再走， **不要带着坑进入下一阶段**。

## 六、免责声明

- 路径基于通用学习经验设计， **具体节奏请按个人情况调整**（全职/兼职/周末制差别很大）。
- 工具版本以主流稳定版为准（pytest 7.x、Playwright 1.4x、requests 2.31+、Locust 2.x）。
- 训练任务中的代码片段建议 **亲手敲**，而不是复制粘贴。
- 本路径不承诺「学完即可就业」，但它覆盖了测试开发岗位的核心技术栈。

> 「测试开发」的核心能力是 **用工程化的方式解决质量保障问题**。路径可以背，能力必须练。
