## 三、面试高频场景题（附思路）

### 3.1 场景：登录功能用例设计

**思路**：
1. 等价类：用户名（有效/无效/边界）、密码（有效/无效/边界）
2. 场景法：正常登录、密码错误、账号不存在、锁定、记住我、密码找回
3. 边界值：用户名长度、密码长度
4. 错误推测：特殊字符、SQL 注入、XSS、验证码、防暴力破解
5. 安全：暴力破解、越权、会话固定

### 3.2 场景：设计一个测试框架

**思路**：
1. 分层设计：unit / api / e2e
2. 核心模块：client、factory、reporter、logger
3. 数据管理：工厂模式 + 外部数据源
4. 报告集成：Allure + pytest-html
5. 工程化：CI/CD、Docker、密钥管理
6. 扩展性：插件机制、自定义 fixture

### 3.3 场景：生产环境接口报错，如何排查？

**思路**：
1. 复现问题：相同请求是否能复现？
2. 查看日志：应用日志、Nginx 日志、数据库日志
3. 检查依赖：数据库、缓存、外部服务
4. 检查代码：近期变更、配置文件
5. 压测验证：是否性能问题
6. 临时方案：回滚、降级
7. 长期方案：根因分析、修复、回归

### 3.4 场景：如何保证测试覆盖率？

**思路**：
1. 代码覆盖率：coverage + pytest-cov
2. 用例覆盖率：需求追溯矩阵
3. 门禁：--cov-fail-under=80
4. 评审：用例评审会
5. 持续改进：每次迭代补充用例

### 3.5 场景：如何处理 flaky 测试？

**思路**：
1. 识别：标记 flaky 用例
2. 隔离：单独运行，不影响其他
3. 排查：等待策略、数据污染、并发问题
4. 修复：显式等待、数据隔离、重试
5. 监控：统计 flaky 率，持续优化

### 4.2 简历描述技巧

**STAR 法则**：

- **Situation**（情境）：项目背景
- **Task**（任务）：你的角色与目标
- **Action**（行动）：你做了什么
- **Result**（结果）：量化成果

**反例**：
> "负责接口自动化测试"

**正例**：
> "主导搭建接口自动化测试套件，覆盖 100+ 接口，200+ 用例，接入 CI/CD 后测试执行时间从 2 小时缩短到 20 分钟，缺陷发现率提升 40%"

**关键词**：
- 主导、搭建、设计、实现、优化
- 从 X 到 Y（量化）
- 提升、缩短、降低、覆盖

## 六、常见坑与踩坑记录

### 6.1 学习坑

| 坑 | 说明 | 解决 |
|---|---|---|
| 只看不练 | 看视频感觉都会了 | 强制动手写代码 |
| 抄代码不报错就跳过 | 不理解原理 | 每段代码写注释、画图 |
| 工具学完就扔 | 工具没用过等于没学 | 每个工具至少 3 个场景 |
| 跳过理论直接学工具 | 思维不到位 | 先理解再动手 |
| 追求大而全 | 想学所有工具 | 主线走通再说 |

### 6.2 项目坑

| 坑 | 说明 | 解决 |
|---|---|---|
| 测试顺序依赖 | 测试 A 影响 B | 每个测试独立 |
| 数据污染 | 测试数据残留 | 用 Mock 或独立库 |
| 硬编码 URL | 环境切换难 | 用环境变量 |
| 报告丢失 | CI 跑完没报告 | 用 artifact 上传 |
| 密钥泄露 | 提交到 Git | 用 Secrets |

### 6.3 面试坑

| 坑 | 说明 | 解决 |
|---|---|---|
| 项目讲不清 | 面试官问懵了 | 准备 5 分钟模板 |
| 不会画架构图 | 纸上谈兵 | 提前画好架构图 |
| 量化数据缺失 | 说不出成果 | 用数字说话 |
| 回答太理论 | 没有实战经验 | 准备 2~3 个故事 |
| 不诚实 | 编造经验 | 不会就说不会 |

## 九、写在最后

测试开发是一条"长期主义"的路线：

- **前 3 个月**：学工具，写代码，建立信心
- **3~6 个月**：做项目，搭框架，建立作品
- **6~9 个月**：找机会，准备面试，进入职场

**最重要的不是路径，而是坚持**。

> 「测试开发的核心能力是用工程化的方式解决质量保障问题。路径可以背，能力必须练。」
